# 重定位结果未知栅格／越界检查修复方案

日期：2026-10-31

本文记录实现方案及执行结果。修复已实现并通过编译和自动化回归测试，尚未提交；实际验收记录见第 11 节。

## 1. 问题与修复原因

修复前，手动给初值重定位和自动全局重定位最终均调用 `PoseInitializer::IsRelocalizationSuccess()`。该函数检查最终扫描匹配得分、粗精位姿一致性，以及启用在线相关匹配时的局部稳定性，但不检查最终位姿所在栅格是否已知、是否越界。

扫描匹配得分来自变换后的激光点，不是机器人位置对应栅格的状态。因此，机器人候选位置落在未知区域时，周围扫描端点仍可能匹配已知墙体，进而通过现有校验。修复前的代码不能保证成功结果处于已加载地图的已知范围内。

修复目标：在接受重定位结果之前增加静态底图栅格有效性检查，拒绝未知区域和地图外的候选位姿。

能力边界：当前算法无法直接区分实际环境是否为陌生环境。本次修复只增加候选位姿的地图区域约束，不提供陌生环境识别能力；不能保证陌生环境下的重定位一定失败。

本问题已通过代码检查及真实地图、激光数据的修复前后对照确认，验收结果见第 11 节。

## 2. 明确的范围约束

- 只判断最终位姿所在栅格是否未知、是否越界。
- 不判断栅格是否空闲；已知占据格也通过新增检查，最终结果仍受原有其他检查约束。
- 不新增占据概率阈值、邻域容差、机器人足迹检查或配置开关。
- 不因手动输入初值处于未知区而直接拒绝请求；初值允许有误差，检查优化后的最终结果。
- 不修复局部模式使用历史 BBS 位姿的问题，仅列为 TODO。
- 不修改运行中 `ConsistencyChecker::RecoverFromLocalMap()` 恢复路径，包括漂移检测后的静态地图恢复。
- 不增加新环境识别、全局误匹配识别、多帧确认或射线冲突检测。
- 不修改 ROS 服务、消息定义及已有重试策略。

## 3. 当前处理链路

| 环节 | 手动给初值 | 自动全局重定位 |
|---|---|---|
| 估计器入口 | `PoseEstimator2D::SetInitialPose()` | `PoseEstimator2D::TriggerGlobalRelocalization()` |
| 匹配地图 | `local_map_updater_->local_submap()` | `global_static_submap_` |
| 初始化器入口 | `RelocalzationOnce()` | `GlobalRelocalzationOnce()` |
| 搜索方式 | 围绕初值快速相关搜索，可配置先做全图匹配 | 全图搜索 |
| 后续优化 | 可选在线相关匹配、Ceres 精配 | 可选在线相关匹配、Ceres 精配 |
| 最终检查 | `IsRelocalizationSuccess()` | `IsRelocalizationSuccess()` |
| 结果接收 | `PoseEstimator2D` 共用成功／失败分支 | 同左 |

手动路径使用的局部地图通常由动态全局地图裁剪而来。初始化器成员 `global_submap_` 名称虽然包含 global，但在手动路径实际上指向局部子图，不能直接把它当作加载时的静态底图。

初始化器报告成功后，估计器接收位姿并切换为 `LOCALIZED`；初始化器失败则进入现有全局重试／最终失败分支。ROS 层还有失败后的触发逻辑，均保持现状。服务响应成功只表示请求已触发，不代表重定位结果成功。

## 4. 判定数据与依据

使用程序内已经加载的 `global_static_submap_->grid()`，不重复读取地图文件。

| 数据 | 本次用途 |
|---|---|
| pbstream | 静态地图的数据来源；加载器已解析，旧格式缺少全局静态子图时已有重建逻辑 |
| 内存静态栅格 | 新增检查的唯一地图依据，提供边界、坐标索引转换和已知状态 |
| PNG／YAML | 本次不读取，不作为判定依据 |
| 动态全局地图、局部地图 | 保留现有匹配用途，不作为新增检查依据 |

选择静态底图的原因：动态地图可能已经把原本未知的区域通过在线观测更新为已知；局部地图还受裁剪范围影响。用它们判断不能保证结果位于已加载静态地图的已知范围。

`Grid2D::IsKnown(index)` 已实现边界和未知值判断。可先调用 `limits().Contains(index)` 区分越界日志，再调用 `IsKnown(index)` 判断未知。

本方案中的“地图未知区域”明确指内存静态底图的未知区域。如果人工编辑过 PNG 且没有同步 pbstream，本修复不保证与编辑后图片一致。

## 5. 修复前后逻辑变化

### 修复前

```text
搜索候选位姿 → 在线匹配／Ceres 精配
  → 最终得分检查
  → 粗精位姿一致性检查
  → 可选局部稳定性检查
  → Success → 接收位姿、切换 LOCALIZED
```

### 修复后

```text
搜索候选位姿 → 在线匹配／Ceres 精配
  → 基础数据检查
  → 查询最终位姿在静态底图中的栅格
      ├─ 越界：拒绝候选
      ├─ 未知：拒绝候选
      └─ 已知：继续（不区分空闲或占据）
  → 原有最终得分、粗精一致性、可选局部稳定性检查
  → Success → 接收位姿、切换 LOCALIZED
```

新增检查返回失败时，沿用两条入口已有的失败处理：清除最终估计结果并设置 `PoseInitializerStatus::Failed`。单个候选失败不一定立即产生最终 `LOC_FAILED`：手动局部失败后，仍允许现有逻辑尝试全局重定位；后续找到合法结果可成功，尝试失败则按原状态机处理。

已知栅格只表示新增检查通过，不保证重定位整体成功。

### 单次失败、外层重试与候选数量

- 单次全局重定位的新增检查失败，会使本次初始化器结果为 `Failed`。但 `TriggerGlobalRelocalization()` 当前不会把 `has_tried_global_relocalization_` 设为 true；该标志为 false 时，外层在首次直接全局失败后仍会再触发一次全局搜索。因此单次全局失败不等于立即终止全部尝试。ROS 层已有失败自动触发逻辑也保持不变。
- 手动局部失败后，按现有状态机尝试全局重定位；全局结果再次经过相同静态栅格检查。
- 搜索器内部评估多个位置／角度候选，但每次成功调用只返回一个最佳粗匹配位姿。在线匹配和 Ceres 沿该结果继续精配，最终检查面对一个最终位姿。
- 最终位姿被拒绝后，本次不会尝试第二名候选，也不保留已拒绝候选的黑名单。外层再次搜索可能得到相同结果。本次不改变搜索策略。


## 6. 最小实现设计

### 6.1 显式传入匹配地图和静态校验地图

调整已有 `PoseInitializer::InitGlobalSubmap()` 接口，使其显式接收两份地图引用：

- 匹配子图：保持现有 `global_submap_` 的职责和使用方式。
- 静态校验子图：新增一个只读共享引用，专供最终位置检查。

调用关系明确如下：

| 调用点 | 匹配子图 | 静态校验子图 |
|---|---|---|
| 手动 `SetInitialPose()` | 当前局部子图 | `global_static_submap_` |
| `TriggerGlobalRelocalization()` | `global_static_submap_` | 同一静态子图 |
| 失败后转全局重试 | `global_static_submap_` | 同一静态子图 |
| 离线初始化器基准工具 | 工具加载的参考子图 | 同一参考子图 |

扩展现有接口是为了满足跨文件传入静态校验数据的实际需求；不新增公共校验工具或通用地图抽象。不增加默认参数把匹配地图自动当成静态地图，避免手动路径静默使用错误依据。

两份引用在现有地图初始化锁内一起设置，沿用当前地图切换时匹配器缓存失效逻辑。停止、重试、换图及复用初始化器时，应保证校验引用对应本轮匹配所使用的地图版本，不残留上一张地图。

### 6.2 在共用最终检查中增加一道检查

在 `IsRelocalizationSuccess()` 中，最终位姿及地图基础检查之后、点云打分之前执行：

1. 确认静态校验子图及其 grid 存在；缺失时返回失败，禁止回退到动态／局部地图。
2. 确认待查询的最终位置是有限数值，避免 NaN／Inf 进入栅格索引转换。
3. 按当前栅格的坐标约定，使用最终估计位姿的位置求 `limits().GetCellIndex(...)`。
4. 索引越界时记录原因并返回失败。
5. 栅格未知时记录原因并返回失败。
6. 已知则继续现有三道校验，不查询空闲／占据概率。

检查对象是当前最终估计位姿的参考点，不扩展成底盘轮廓或激光端点检查。实现时必须核实最终位姿和静态栅格的坐标约定，使用 `MapLimits` 完成索引转换，不能把子图中心当作额外坐标偏移重复叠加。

逻辑较短时直接保留在该函数内；确需辅助方法时使用类私有方法，不为此新增生产代码文件。

### 6.3 日志

分别记录静态地图不可用、最终位置无效、越界和未知四种失败原因。未知／越界日志包含最终位置和栅格索引，便于与地图对应；不新增 ROS 错误码。

## 8. 验证方案与验收标准

| 用例 | 预期 |
|---|---|
| 最终位置在静态底图已知空闲格 | 新增检查通过，继续原检查 |
| 最终位置在静态底图已知占据格 | 新增检查通过，证明没有加入空闲判断 |
| 最终位置在地图内部未知格 | 新增检查失败，不接受该候选 |
| 最终位置在地图四侧边界之外 | 新增检查失败，日志区分越界 |
| 边界内外相邻位置、非零地图坐标范围 | 索引转换正确，避免原点／坐标顺序错误 |
| 动态／局部地图已知，但静态底图未知 | 失败，证明依据是静态底图 |
| 静态校验地图缺失或最终位置非有限值 | 失败，不跳过检查或发生非法索引访问 |
| 手动、全局两条入口 | 均执行新增检查，失败进入已有失败分支 |
| 初始化器停止后重试、切换另一张地图 | 使用本轮静态地图，不使用旧地图引用 |
| 原有正常全局定位样本 | 结果不因本次修改退化；基准工具可构建并运行 |

为验证“得分不能替代位置检查”，应构造最终位置未知、周围激光端点可匹配已知障碍的样本，确认新增检查明确拒绝，而不是仅观察到原有得分检查失败。

测试夹具应控制现有 BBS 一致性检查的影响，分别验证新增栅格检查和入口失败传播，不能把历史 BBS 问题引起的失败当作本修复有效的证据。不得为了测试顺便修复该问题。

验收要求：涉及目标编译通过；新增回归测试实际执行通过；确认手动／全局入口和基准工具均传入正确地图；确认没有引入空闲判断、漂移恢复路径变化或 BBS 逻辑修改。

## 9. TODO 与能力边界

### TODO：局部模式使用历史 BBS 位姿

当前 `IsRelocalizationSuccess()` 无条件读取 `last_global_bbs_pose_`，但该值仅在全局搜索路径更新，局部路径不更新，`ResetStatus()` 也不清除。局部结果可能与默认原点或历史全局结果比较，导致错误拒绝并退回全局搜索。

该问题本次只记录，不改变相关赋值、检查条件、阈值或重置逻辑。

### 不覆盖的恢复路径

运行中 `RecoverFromLocalMap()` 及漂移恢复不会获得本次新增保证。本方案的“拒绝未知区域结果”仅适用于 `PoseInitializer` 的手动给初值和全局重定位链路。

### 无法直接区分陌生环境

当前算法依据扫描与地图的匹配得分、位姿一致性及局部稳定性判断重定位结果，无法直接判断机器人实际处于已建图环境还是陌生环境。本次新增的未知／越界检查也不具备这种识别能力。

**本次修复无法处理以下情况：机器人实际处于陌生但结构相似的环境，扫描与旧地图的相似结构匹配，通过匹配得分及其他现有校验，且最终匹配位姿恰好落在旧地图的已知区域。此时未知／越界检查会通过，算法仍可能错误报告重定位成功。**

“匹配得分达标”和“候选位姿位于已知栅格”都不能证明实际环境就是地图对应的环境。新增检查只能拒绝最终位姿落在静态底图未知区域或地图外的候选结果，不能拒绝所有陌生相似环境中的误匹配。

因此，本次修复的验收标准是未知／越界候选被拒绝，而不是所有陌生环境都必须重定位失败。第 11 节的陌生场景回放用于验证拦截效果并暴露这一能力边界；其中已知区域误匹配仍被接受，不等于未知／越界检查失效。

识别上述陌生相似环境误匹配需要额外的判别证据及独立方案，不属于本次修复。静态地图内部的未知小孔仍按同一规则拒绝，本次不添加容差。

## 11. 测试验收结果（14floor_ekf_chassis）

### 结论

本轮真实数据确认新增未知栅格检查有效：相同 60 帧对照中，有 15 帧从修复前通过变为修复后拒绝，拒绝原因均为最终位置处于静态底图未知栅格。完整回放也实际触发了 6 次未知格拒绝。

但陌生场景仍会被错误匹配到已知区域：完整回放有 2 次重定位被接受，结束时状态为 `LOC_SUCCESS`。因此本轮验证通过的是“未知区结果拒绝”，不是“陌生场景必然失败”。本轮没有触发越界分支。

### 输入与条件

- bag： `/home/dex/rosbag/dynamic_mapping2d`，完整 1 倍速回放，时长约 148.97 秒。
- 地图： `/home/dex/.dexe/data/maps/14floor_ekf_chassis/slam/map.pbstream`，实际加载 `/tmp/relocalization_14floor_acceptance/maps/14floor_ekf_chassis/slam/map.pbstream` 副本。
- 静态栅格 822 × 823，分辨率 0.05 m，676506 格中 221795 格已知。
- 使用 `dexe_localization_2d.lua` 配置；因本机 GPU 驱动不可用，在临时配置中将全局匹配器设为 CPU，最小得分保持 0.3。使用修复版定位节点及仅移除新增检查的临时对照程序，其他匹配参数一致。
- 独立本机 ROS 域 174，自动加载地图，无手动初值，自动全局重定位。
- 原始地图及 bag 内容哈希测试前后一致；原有工作区更改保留，未暂存、未提交。

### 完整回放

| 指标 | 结果 |
|---|---|
| 旁路收到前／后激光 | 2247 / 2208 帧，与 bag 元数据一致 |
| 全局重定位尝试 | 8 次 |
| 未知格检查拒绝 | 6 次 |
| 越界检查拒绝 | 0 次 |
| 初始化器成功且估计器接收 | 2 次 |
| 观察到进入 `LOC_SUCCESS` | 2 次状态切换 |
| 最后状态 | `LOC_SUCCESS`（4） |
| 播放器、定位节点退出码 | 均为 0 |

两次被接受的最终位置分别为 `(-18.5755, 10.6749)` 和 `(-18.5294, 10.9413)`。通过临时只读工具查询同一 pbstream，均属于已知格，所以按约定不应由新增检查拒绝。

未知区拒绝日志示例：

```text
Relocalization validation failed: unknown static grid cell at -20.9229 9.55287, cell=436 743
```

观察器使用兼容的 `/clock` 订阅 QoS，收到仿真时钟范围 `1787891443.0931706` 至 `1787891592.0478637`。旁路 IMU 和里程计各收到 14893 帧，少于 bag 元数据中的各 14898 帧；这些是旁路计数，不等同于定位节点的精确消费计数。

双方使用同一 bag、随机种子 42、60 帧及双雷达预处理；预热一帧不计入下表。对照程序仅移除本次新增检查，其余算法一致。
