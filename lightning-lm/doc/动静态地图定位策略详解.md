## 1. 定位策略概述

### 1.1 核心思想

Lightning-LM的定位策略是**静态为主，动态为辅**的双层融合定位：

```
定位输入
    ↓
当前帧点云
    ↓
┌──────────────────────────────┐
│   地图融合定位引擎            │
│                              │
│  静态地图 ────┐              │
│  (高质量)     ├──► NDT融合  ─┼──► 定位结果
│               │              │
│  动态地图 ────┘              │
│  (实时更新)                  │
└──────────────────────────────┘
    ↓
高精度位姿
```

**设计理念**：
- 🎯 **静态地图**：提供稳定的全局定位基准
- 🔄 **动态地图**：补充环境变化信息
- 🤝 **融合定位**：两者无缝融合，互补优势

### 1.2 与传统方法对比

| 方法 | 优点 | 缺点 | Lightning-LM方案 |
|------|------|------|-----------------|
| **仅静态地图** | 稳定、高质量 | 无法适应变化 | ❌ 单一依赖 |
| **仅动态地图** | 适应性强 | 累积误差大 | ❌ 单一依赖 |
| **独立双地图** | 可对比验证 | 计算量翻倍 | ❌ 效率低 |
| **融合双地图** | 稳定+适应 | 需要融合策略 | ✅ **采用方案** |

### 1.3 关键技术

```
融合定位 = NDT + 双层地图 + 动态更新

其中：
  - NDT：正态分布变换配准算法
  - 双层地图：静态层 + 动态层
  - 动态更新：实时累积点云到动态层
```

## 2. 地图融合机制

### 2.1 融合架构

```cpp
// TiledMap::SetNewTargetForNDT() - 核心融合函数
template <class T>
void SetNewTargetForNDT(T ndt) {
    bool has_cloud = false;
    
    // 1. 添加静态地图
    {
        UL lock(static_data_mutex_);
        for (auto& idx : loaded_chunks_) {
            if (!static_chunks_[idx]->cloud_->empty()) {
                has_cloud = true;
            }
            ndt->AddTarget(static_chunks_[idx]->cloud_);  // 添加静态Chunk
        }
    }
    
    // 2. 添加动态地图
    {
        UL lock(dynamic_data_mutex_);
        for (auto& idx : loaded_chunks_) {
            if (dynamic_chunks_.find(idx) != dynamic_chunks_.end()) {
                if (dynamic_chunks_[idx]->cloud_ != nullptr) {
                    has_cloud = true;
                    ndt->AddTarget(dynamic_chunks_[idx]->cloud_);  // 添加动态Chunk
                }
            }
        }
    }
    
    // 3. 计算融合后的NDT体素网格
    ndt->ComputeTargetGrids();
    
    // 4. 初始化NDT
    if (has_cloud) {
        ndt->initCompute();
    }
}
```

### 2.2 融合过程详解

#### 2.2.1 Chunk遍历

```
当前加载的Chunks (假设load_map_size=2):

Grid坐标:
  (-1,1)  (0,1)  (1,1)
  (-1,0)  (0,0)  (1,0)  ← 车辆当前位置
  (-1,-1) (0,-1) (1,-1)

每个Grid包含：
  - 1个静态Chunk (static_chunks_[grid])
  - 0或1个动态Chunk (dynamic_chunks_[grid])
```

**遍历逻辑**：
```cpp
for (auto& idx : loaded_chunks_) {  // idx = Vec2i Grid坐标
    // 步骤1：添加静态点云
    CloudPtr static_cloud = static_chunks_[idx]->cloud_;
    ndt->AddTarget(static_cloud);
    
    // 步骤2：添加动态点云（如果存在）
    if (dynamic_chunks_.find(idx) != dynamic_chunks_.end()) {
        CloudPtr dynamic_cloud = dynamic_chunks_[idx]->cloud_;
        if (dynamic_cloud != nullptr) {
            ndt->AddTarget(dynamic_cloud);
        }
    }
}
```

#### 2.2.2 点云添加到NDT

```cpp
// VoxelGridCovariance::AddTarget() - 添加目标点云
void AddTarget(PointCloudPtr target) {
    for (size_t cp = 0; cp < target->points.size(); ++cp) {
        // 1. 计算点所属的体素Key (x,y,z网格索引)
        auto key = Pt2Key(target->points[cp].getVector3fMap());
        
        // 2. 查找或创建体素
        auto iter = leaves_.find(key);
        if (iter == leaves_.end()) {
            // 体素不存在，创建新体素
            Leaf l;
            l.points_.emplace_back(target->points[cp].getVector3fMap());
            l.nr_points = 1;
            leaves_.insert({key, l});
        } else {
            // 体素已存在，添加点到该体素
            auto& leaf = iter->second;
            leaf.points_.emplace_back(target->points[cp].getVector3fMap());
            leaf.nr_points++;
        }
    }
}
```

**关键点**：
- 静态和动态点云**共享同一个NDT体素网格**
- 如果静态点和动态点落在同一体素，它们会**共同影响**该体素的分布
- 后面的`ComputeTargetGrids()`会统一计算所有体素的高斯分布

#### 2.2.3 体素Key计算

```cpp
inline Eigen::Vector3i Pt2Key(const Eigen::Vector3f &pt) const {
    // inverse_leaf_size_ = 1.0 / resolution_  (resolution_ = 1.0m)
    // 例如：pt = (2.3, 1.8, 0.5) → key = (2, 2, 1)
    return (pt * inverse_leaf_size_[0]).array().round().template cast<int>();
}
```

**示例**：
```
NDT分辨率: 1.0m

点的世界坐标 → 体素Key:
  (0.2, 0.3, 0.1)   → (0, 0, 0)
  (1.5, 1.8, 0.9)   → (2, 2, 1)
  (2.3, 1.8, 0.5)   → (2, 2, 1)  ← 与上一个点在同一体素
  (-0.5, 0.2, 1.1)  → (0, 0, 1)
```

### 2.3 体素网格计算

#### 2.3.1 高斯分布估计

```cpp
// VoxelGridCovariance::ComputeTargetGrids()
void ComputeTargetGrids() {
    std::for_each(leaves_.begin(), leaves_.end(), [this](auto& it) {
        Leaf& leaf = it.second;
        
        // 1. 累积点的和与协方差
        for (auto& pt : leaf.points_) {
            Eigen::Vector3d pt3d(pt[0], pt[1], pt[2]);
            leaf.mean_ += pt3d;           // 累加点
            leaf.cov_ += pt3d * pt3d.transpose();  // 累加外积
        }
        
        // 2. 计算均值
        leaf.mean_ /= leaf.nr_points;
        
        // 3. 检查点数是否足够
        if (leaf.nr_points < min_points_per_voxel_) {  // 默认6
            return;  // 点太少，跳过
        }
        
        // 4. 计算协方差矩阵
        // Cov = E[XX^T] - E[X]E[X]^T
        leaf.cov_ = (leaf.cov_ - 2 * (pt_sum * leaf.mean_.transpose())) / leaf.nr_points 
                    + leaf.mean_ * leaf.mean_.transpose();
        leaf.cov_ *= (leaf.nr_points - 1.0) / leaf.nr_points;
        
        // 5. 特征值分解
        Eigen::SelfAdjointEigenSolver<Eigen::Matrix3d> eigensolver;
        eigensolver.compute(leaf.cov_);
        Eigen::Matrix3d eigen_val = eigensolver.eigenvalues().asDiagonal();
        auto evecs = eigensolver.eigenvectors();
        
        // 6. 避免奇异矩阵（最小特征值限制）
        double min_covar_eigvalue = min_covar_eigvalue_mult_ * eigen_val(2, 2);
        if (eigen_val(0, 0) < min_covar_eigvalue) {
            eigen_val(0, 0) = min_covar_eigvalue;
            if (eigen_val(1, 1) < min_covar_eigvalue) {
                eigen_val(1, 1) = min_covar_eigvalue;
            }
            leaf.cov_ = evecs * eigen_val * evecs.inverse();
        }
        
        // 7. 计算协方差逆矩阵（用于NDT匹配）
        leaf.icov_ = leaf.cov_.inverse();
        
        // 8. 检查是否有效
        if (leaf.icov_.maxCoeff() == std::numeric_limits<float>::infinity() ||
            leaf.icov_.minCoeff() == -std::numeric_limits<float>::infinity()) {
            leaf.nr_points = -1;  // 标记为无效
        }
    });
}
```

#### 2.3.2 融合体素示例

```
体素 Key = (10, 20, 5)

静态地图贡献:
  点数: 50点
  来源: Chunk (0,1) 静态层
  
动态地图贡献:
  点数: 15点
  来源: Chunk (0,1) 动态层
  
融合后:
  总点数: 65点
  均值: μ = (Σ所有65点) / 65
  协方差: Σ = 根据所有65点计算
  
结果:
  该体素的高斯分布由静态+动态共同决定
  静态点更多 → 静态地图影响更大
  动态点补充 → 适应环境变化
```

### 2.4 融合策略特点

#### 2.4.1 无差别融合

```
特点：
  - 静态点和动态点在NDT中**平等对待**
  - 没有显式的权重区分
  - 通过点数自然形成权重

优势：
  ✅ 算法简单，计算高效
  ✅ 静态地图点多，自然权重高
  ✅ 动态地图点少，作为补充

体现：
  静态层: 50,000点/Chunk
  动态层: 10,000点/Chunk (更新累积)
  ─────────────────────────
  融合后: 静态占83%，动态占17%
```

#### 2.4.2 空间互补

```
场景1: 静态地图完整的区域
  ┌─────────────┐
  │ ████████    │  静态: 密集
  │ ████████    │  动态: 稀疏或无
  │ ████████    │
  └─────────────┘
  结果: 主要依赖静态地图

场景2: 环境变化的区域（如停车位）
  ┌─────────────┐
  │ ████░░░░    │  静态: 空停车位
  │ ████▓▓▓▓    │  动态: 当前停放的车
  │ ████░░░░    │  ▓ = 动态层新增点
  └─────────────┘
  结果: 动态层补充新障碍物

场景3: 静态地图缺失区域
  ┌─────────────┐
  │             │  静态: 无
  │    ▓▓▓▓     │  动态: 实时累积
  │    ▓▓▓▓     │
  └─────────────┘
  结果: 完全依赖动态地图
```

## 3. NDT匹配原理

### 3.1 NDT配准流程

```
当前帧点云 (Source)
    ↓
对每个源点 p_i:
    ├─ 1. 计算所在体素 key_i
    ├─ 2. 查找该体素的高斯分布 (μ, Σ)
    ├─ 3. 计算概率密度
    │     P(p_i) = exp(-0.5 * (p_i - μ)^T * Σ^(-1) * (p_i - μ))
    └─ 4. 累积所有点的概率
    ↓
优化位姿变换 T:
    最大化 Σ P(T * p_i)
    ↓
输出最优位姿
```

### 3.2 融合地图在NDT中的作用

```cpp
// 定位过程
bool LidarLoc::Localize(SE3& pose, double& confidence, 
                        CloudPtr input, CloudPtr output,
                        bool use_rough_res) {
    // 1. 获取融合后的NDT（包含静态+动态）
    UL lock(match_mutex_);
    NDTType::Ptr ndt = use_rough_res ? pcl_ndt_rough_ : pcl_ndt_;
    
    // 2. 设置当前帧点云为源点云
    ndt->setInputSource(input);
    
    // 3. NDT配准
    Eigen::Matrix4f guess_pose = pose.matrix().cast<float>();
    ndt->align(*output, guess_pose);
    
    // 4. 获取结果
    Eigen::Matrix4f trans = ndt->getFinalTransformation();
    confidence = ndt->getTransformationProbability();
    
    pose = SE3(Quatd(trans.block<3, 3>(0, 0).cast<double>()), 
               trans.block<3, 1>(0, 3).cast<double>());
    
    return (confidence > min_init_confidence_);
}
```

### 3.3 匹配得分计算

```
对于当前帧的每个点 p:

1. 变换到地图坐标系: p' = T * p

2. 查找所在体素的高斯分布 N(μ, Σ)
   - μ: 由静态+动态点共同决定
   - Σ: 由静态+动态点共同决定

3. 计算似然:
   L(p') = -0.5 * (p' - μ)^T * Σ^(-1) * (p' - μ)

4. 总得分:
   Score = Σ L(p_i') for all points

越接近0越好（负对数似然）
```

**融合的影响**：
```
纯静态地图:
  体素(10,20,5): μ_static, Σ_static
  匹配得分: Score_static

融合地图:
  体素(10,20,5): μ_fused, Σ_fused
  - μ_fused 更接近实际环境
  - Σ_fused 反映当前分布
  匹配得分: Score_fused (通常更高)
```

## 4. 定位流程详解

### 4.1 完整流程

```
[定位帧到达]
    ↓
AssignLOPose()  # 获取LiDAR Odom位姿
AssignDRPose()  # 获取Dead Reckoning位姿
    ↓
构建位姿初值
    ├─ guess_from_lo
    ├─ guess_from_dr
    └─ guess_from_self
    ↓
LoadOnPose(guess_from_dr)  ◄─── 加载地图
    ├─ 静态Chunks加载
    └─ 动态Chunks加载/创建
    ↓
地图更新? ────┐
    │         │
    No        Yes
    │         │
    │         ↓
    │    UpdateGlobalMap()  ◄─── 重建NDT
    │         ├─ SetNewTargetForNDT()  ◄─── 融合静态+动态
    │         ├─ ComputeTargetGrids()  ◄─── 计算高斯分布
    │         └─ initCompute()
    │         │
    └─────────┘
    ↓
NDT配准
    ├─ 尝试LO预测
    ├─ 尝试DR预测（如需要）
    └─ 尝试Self预测（如需要）
    ↓
选择最佳结果
    ↓
质量评估
    ├─ 匹配分值
    ├─ 与预测的偏差
    └─ 平滑性检查
    ↓
UpdateDynamicCloud()  ◄─── 更新动态层
    ↓
输出定位结果
```

### 4.2 地图加载与NDT更新

```cpp
void LidarLoc::Align(const CloudPtr& input) {
    // ... 位姿预测 ...
    
    // 1. 根据预测位姿加载地图
    map_->LoadOnPose(guess_from_dr);
    // 此时可能加载了新的Chunk，或卸载了远离的Chunk
    
    // 2. 地图更新检测由独立线程处理
    // UpdateMapThread会检测map_updated_标志

void LidarLoc::UpdateMapThread() {
    while (!update_map_quit_) {
        // 检查地图是否更新
        if (map_->MapUpdated() || map_->DynamicMapUpdated()) {
            // 重新构建NDT（融合静态+动态）
            UpdateGlobalMap();
            
            // 更新UI显示
            if (ui_) {
                ui_->UpdatePointCloudGlobal(map_->GetStaticCloud());
                ui_->UpdatePointCloudDynamic(map_->GetDynamicCloud());
            }
            
            // 清除更新标记
            map_->CleanMapUpdate();
        }
        
        usleep(10000);  // 10ms
    }
}

bool LidarLoc::UpdateGlobalMap() {
    // 1. 创建NDT对象
    NDTType::Ptr ndt(new NDTType());
    ndt->setResolution(1.0);  // 1m分辨率
    ndt->setNeighborhoodSearchMethod(pclomp::DIRECT7);
    ndt->setStepSize(0.1);
    ndt->setMaximumIterations(4);
    ndt->setNumThreads(4);
    
    // 2. 设置融合地图为目标（核心步骤）
    map_->SetNewTargetForNDT(ndt);
    //    ↑
    //    └─── 这里完成静态+动态的融合
    
    ndt->initCompute();
    
    // 3. 原子操作更新NDT指针
    UL lock(match_mutex_);
    pcl_ndt_ = ndt;
    
    // 4. 粗分辨率NDT（用于初始化）
    if (!loc_inited_) {
        NDTType::Ptr ndt_rough(new NDTType());
        ndt_rough->setResolution(5.0);  // 5m分辨率
        // ... 配置 ...
        map_->SetNewTargetForNDT(ndt_rough);
        pcl_ndt_rough_ = ndt_rough;
    }
    
    return true;
}
```

## 5. 权重与优先级策略

### 5.1 隐式权重机制

Lightning-LM采用**点数驱动的隐式权重**，而非显式权重配置。

#### 5.1.1 体素内权重

```
体素 (i, j, k) 内的点分布:

静态地图: N_static 个点
动态地图: N_dynamic 个点

高斯分布计算:
  μ = (Σ所有点) / (N_static + N_dynamic)
  Σ = 基于所有点的协方差

隐式权重:
  w_static = N_static / (N_static + N_dynamic)
  w_dynamic = N_dynamic / (N_static + N_dynamic)
```

**示例**：
```
体素A:
  静态: 50点, 动态: 10点
  → 静态权重 83%, 动态权重 17%

体素B:
  静态: 30点, 动态: 30点
  → 静态权重 50%, 动态权重 50%

体素C:
  静态: 0点, 动态: 20点
  → 静态权重 0%, 动态权重 100%
```

#### 5.1.2 全局权重分布

```
典型场景统计:

静态地图:
  - 50,000点/Chunk (100m×100m)
  - 密度: 5点/m²

动态地图:
  - 初期: ~1,000点/Chunk
  - 累积后: ~10,000点/Chunk
  - 密度: 0.1-1点/m²

融合后总权重:
  静态: 80-95%
  动态: 5-20%
```

### 5.2 空间优先级

#### 5.2.1 Chunk级优先级

```
优先级判定:

1. 两层都有 → 融合使用
   ├─ 静态Chunk: 加载
   └─ 动态Chunk: 加载（如果存在）

2. 仅静态 → 静态主导
   ├─ 静态Chunk: 加载
   └─ 动态Chunk: 不存在或为空

3. 仅动态 → 动态补充
   ├─ 静态Chunk: 不存在
   └─ 动态Chunk: 加载（罕见情况）
```

#### 5.2.2 体素级优先级

```
体素匹配优先级:

1. 静态+动态都有点
   → 使用融合分布
   → 匹配得分高

2. 仅静态有点
   → 使用静态分布
   → 可靠性高

3. 仅动态有点
   → 使用动态分布
   → 适应性强

4. 两者都无点
   → 该体素无效
   → 不参与匹配
```

## 6. 动态更新策略

### 6.1 更新触发条件

```cpp
// 在Align()中的动态更新逻辑
bool should_update = 
    options_.update_dynamic_cloud_ &&           // 功能开关
    loc_success &&                              // 定位成功
    score > options_.update_lidar_loc_score_ && // 分值 > 2.2
    (distance > options_.update_kf_dis_ ||      // 距离 > 5m
     time_diff > options_.update_kf_time_);     // 时间 > 10s

if (should_update) {
    // Z轴过滤
    CloudPtr filtered = FilterZ(input, 0.5, options_.filter_z_max_);
    
    // 转换到世界坐标系
    CloudPtr cloud_world(new PointCloudType);
    pcl::transformPointCloud(*filtered, *cloud_world, 
                            current_pose_esti.matrix());
    
    // 更新动态层
    map_->UpdateDynamicCloud(cloud_world, true);
    
    last_dyn_upd_pose_ = TimedPose(current_time, current_pose_esti);
}
```

### 6.2 更新策略图解

```
定位质量判定树:

定位成功?
    ├─ No  → 跳过更新
    └─ Yes → 检查分值
              │
              ├─ score ≤ 2.2 → 跳过更新（质量不够）
              └─ score > 2.2 → 检查间隔
                                │
                                ├─ 距离 < 5m && 时间 < 10s
                                │   → 跳过（太频繁）
                                │
                                └─ 距离 ≥ 5m || 时间 ≥ 10s
                                    → 执行更新
```

### 6.3 更新对定位的反馈

```
定位循环与动态更新:

帧 N:
  定位 → score=2.5, pos=(100,200)
  更新动态层 → 添加1000点
  map_->DynamicMapUpdated() = true

帧 N+1:
  [UpdateMapThread检测到更新]
  重建NDT → 融合新的动态点
  定位 → score=2.6 (提升！)
  
帧 N+2:
  定位 → score=2.6
  不满足更新条件（距离<5m）
  
帧 N+10:
  定位 → score=2.7, 距离>5m
  更新动态层 → 继续累积
```

### 6.4 动态层容量管理

```cpp
// 在UpdateDynamicCloud()中
for (const auto& g : updated_grids) {
    size_t full_size = dynamic_chunks_[g]->cloud_->size();
    
    // 策略1: 超过1.5倍上限，体素化降采样
    if (full_size > 1.5 * options_.max_pts_in_dyn_chunk_) {
        dynamic_chunks_[g]->cloud_ = 
            math::VoxelGrid(dynamic_chunks_[g]->cloud_, 0.5);
    }
    
    // 策略2: 超过上限，移除70%旧点
    if (remove_old && full_size > options_.max_pts_in_dyn_chunk_) {
        size_t remove_cnt = size_t(0.7 * full_size);
        dynamic_chunks_[g]->cloud_->points.erase(
            dynamic_chunks_[g]->cloud_->points.begin(),
            dynamic_chunks_[g]->cloud_->points.begin() + remove_cnt);
        dynamic_chunks_[g]->cloud_->width = full_size - remove_cnt;
    }
}
```

```

0点 ─────► 累积 ─────► 50,000点 ───────► 继续添加
                        ▲                    │
                        └─ max_pts          ↓
                                       75,000点
                                            │
                                            ↓
                                    触发体素化降采样
                                            │
                                            ↓
                                       回到 ~40,000点
```
