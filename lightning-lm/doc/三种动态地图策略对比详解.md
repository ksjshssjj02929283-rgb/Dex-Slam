## 1. 策略概述

### 1.1 三种策略定义

```cpp
/// 在tiled_map.h中定义
enum class DynamicCloudPolicy {
    /// 短时间保留，车辆移出该区域就会清空
    SHORT = 0,

    /// 长时间保留在内存，车辆移出区域后仍然保留，但不会存盘并在下次开机时使用
    LONG,

    /// 更长时间的保留，会存盘，下次运行也会读取，超过一定时间后才会清除
    PERSISTENT,
};
```

### 1.2 核心差异总览

| 特性 | 不使用动态地图 | SHORT策略 | LONG策略 | PERSISTENT策略 |
|------|---------------|-----------|----------|----------------|
| **动态层更新** | ❌ 不更新 | ✅ 实时更新 | ✅ 实时更新 | ✅ 实时更新 |
| **区域卸载时** | N/A | 🗑️ 清空内存 | 💾 保留内存 | 💾 保留+存盘 |
| **程序启动时** | 仅静态 | 仅静态 | 仅静态 | 静态+动态 |
| **程序退出时** | N/A | ❌ 不保存 | ❌ 不保存 | ✅ 保存文件 |
| **内存占用** | 最低 | 中等 | 较高 | 较高 |
| **磁盘写入** | 无 | 无 | 无 | 频繁 |
| **适应性** | 差 | 中等 | 高 | 最高 |
| **长期运行** | 可能退化 | 单次有效 | 单次有效 | 跨会话有效 |

## 2. 策略配置

### 2.1 配置文件设置

```yaml
# config/default.yaml

maps:
  # 动态地图策略选择
  dyn_cloud_policy: persistent     # short / long / persistent
  
  # 动态层管理参数
  max_pts_dyn_chunk: 50000         # 每个动态Chunk最大点数
  load_map_size: 2                 # 加载范围（chunk数量）
  unload_map_size: 3               # 卸载阈值（chunk数量）
  
  # 存储控制（主要影响PERSISTENT策略）
  load_dyn_cloud: true             # 启动时是否加载动态点云
  save_dyn_when_quit: true         # 退出时是否保存
  save_dyn_when_unload: false      # 卸载时是否保存
  delete_when_unload: false        # 卸载时是否清空内存

lidar_loc:
  # 动态地图更新控制
  update_dynamic_cloud: true       # 是否更新动态层（设为false则不使用动态地图）
  update_lidar_loc_score: 2.2      # 更新时的匹配分值阈值
  update_kf_dis: 5.0               # 更新距离间隔(m)
  update_kf_time: 10.0             # 更新时间间隔(s)
```

### 2.2 代码初始化

```cpp
/// 在lidar_loc.cc的Init()函数中
bool LidarLoc::Init(const std::string& config_path) {
    YAML_IO yaml(config_path);
    
    // 读取策略配置
    std::string map_policy = yaml.GetValue<std::string>("maps", "dyn_cloud_policy");
    if (map_policy == "short") {
        options_.map_option_.policy_ = TiledMap::DynamicCloudPolicy::SHORT;
    } else if (map_policy == "long") {
        options_.map_option_.policy_ = TiledMap::DynamicCloudPolicy::LONG;
    } else if (map_policy == "persistent") {
        options_.map_option_.policy_ = TiledMap::DynamicCloudPolicy::PERSISTENT;
    }
    
    // 读取存储控制参数
    options_.map_option_.delete_when_unload_ = yaml.GetValue<bool>("maps", "delete_when_unload");
    options_.map_option_.load_dyn_cloud_ = yaml.GetValue<bool>("maps", "load_dyn_cloud");
    options_.map_option_.save_dyn_when_quit_ = yaml.GetValue<bool>("maps", "save_dyn_when_quit");
    options_.map_option_.save_dyn_when_unload_ = yaml.GetValue<bool>("maps", "save_dyn_when_unload");
    
    // 创建地图对象
    map_ = std::make_shared<TiledMap>(options_.map_option_);
    map_->LoadMapIndex();  // 加载静态地图索引
    
    return true;
}
```

## 3. 定位流程对比

### 3.1 通用定位流程（所有策略共同部分）

```cpp
/// 在lidar_loc.cc的Align()函数中（共同部分）
void LidarLoc::Align(CloudPtr input) {
    // 1. 预处理
    AssignLOPose(current_time);
    AssignDRPose(current_time);
    
    // 2. 获取初始位姿估计
    SE3 guess_from_lo = last_abs_pose_;
    if (last_lo_pose_set_ && current_lo_pose_set_) {
        const SE3 delta = last_lo_pose_.inverse() * current_lo_pose_;
        guess_from_lo = last_abs_pose_ * delta;
    }
    
    // 3. 加载地图（所有策略都会加载静态+动态）
    map_->LoadOnPose(guess_from_dr);
    
    // 4. NDT匹配定位（使用静态+动态融合地图）
    SE3 current_pose_esti = guess_from_lo;
    double fitness_score = 0;
    CloudPtr output_cloud(new PointCloudType);
    bool loc_success = Localize(current_pose_esti, fitness_score, input, output_cloud);
    
    // 5. 更新结果
    current_abs_pose_ = current_pose_esti;
    current_score_ = fitness_score;
    
    // 6. 动态地图更新（策略差异点）
    // ...
}
```

### 3.2 策略1: 不使用动态地图

```yaml
# 配置
lidar_loc:
  update_dynamic_cloud: false  # 关闭动态地图更新
```

**流程特点**：
```cpp

    // 1-5 步与通用流程相同
    
    // 6. 动态地图更新（跳过）
    if (options_.update_dynamic_cloud_ && ...) {  // false，跳过
        // 不执行更新
    }
    
    // 结果：
    // - 只使用静态地图定位
    // - 动态层始终为空
    // - map_->SetNewTargetForNDT() 只添加静态点云
```

**NDT匹配时地图构成**：
```
SetNewTargetForNDT():
  ├─ 静态层: ✅ 添加所有loaded chunks
  └─ 动态层: ❌ 空（未更新过）
  
结果: 纯静态地图定位
```

### 3.3 策略2: SHORT策略（短期保留）

```yaml
# 配置
maps:
  dyn_cloud_policy: short
  save_dyn_when_quit: false       # 不影响SHORT
  save_dyn_when_unload: false     # 不影响SHORT
  delete_when_unload: false       # 不影响SHORT（SHORT强制清空）
  
lidar_loc:
  update_dynamic_cloud: true      # 开启动态更新
```

**流程特点**：
```cpp
void LidarLoc::Align(CloudPtr input) {
    // 1-5 步与通用流程相同
    
    // 6. 动态地图更新
    bool score_cond = current_score_ > options_.update_lidar_loc_score_;  // 2.2
    
    if (options_.update_dynamic_cloud_ && loc_success &&
        (distance > update_kf_dis_ || time > update_kf_time_)) {
        if (score_cond) {
            // Z轴过滤
            CloudPtr input_z_filter = ZAxisFilter(input);
            
            // 变换到世界坐标系
            CloudPtr cloud_world(new PointCloudType());
            pcl::transformPointCloud(*input_z_filter, *cloud_world, 
                                   current_pose_esti.matrix());
            
            // 更新动态层
            map_->UpdateDynamicCloud(cloud_world, true);
        }
    }
}

/// 在tiled_map.cc的LoadOnPose()中（卸载逻辑）
void TiledMap::LoadOnPose(const SE3& pose) {
    // ... 加载逻辑 ...
    
    // 卸载过远的区块
    for (auto iter = loaded_chunks_.begin(); iter != loaded_chunks_.end();) {
        Vec2i g = *iter;
        int n = abs((g - this_grid)[0]) + abs((g - this_grid)[1]);
        
        if (n > options_.unload_map_size_) {  // 超过3个chunk距离
            // SHORT策略：直接清空动态层
            if (options_.policy_ == DynamicCloudPolicy::SHORT && 
                dynamic_chunks_.find(g) != dynamic_chunks_.end()) {
                dynamic_chunks_[g]->cloud_ = nullptr;  // 清空内存
                dynamic_map_updated_ = true;
                LOG(INFO) << "SHORT策略：清空动态Chunk " << g.transpose();
            }
            
            iter = loaded_chunks_.erase(iter);
        } else {
            iter++;
        }
    }
}
```

**NDT匹配时地图构成**：
```
当前区域:
  SetNewTargetForNDT():
    ├─ 静态层: ✅ 当前区域的静态chunks
    └─ 动态层: ✅ 当前区域的动态chunks（实时累积）
    
离开区域后:
  SetNewTargetForNDT():
    ├─ 静态层: ✅ 新区域的静态chunks
    └─ 动态层: ❌ 旧区域动态层已清空，新区域从零开始
```

**生命周期**：
```
时刻T0: 进入区域A
  └─► 动态层A: 空
  
T0~T10: 在区域A内移动
  └─► 动态层A: 累积点云（0 → 30k点）
  
T10: 离开区域A（距离>300m）
  └─► 动态层A: 清空（30k → 0点）
  
T20: 再次进入区域A
  └─► 动态层A: 空（重新开始）
```

### 3.4 策略3: LONG策略（长期保留）

```yaml
# 配置
maps:
  dyn_cloud_policy: long
  save_dyn_when_quit: false       # LONG不存盘
  save_dyn_when_unload: false
  delete_when_unload: false       # 保留在内存
```

**流程特点**：
```cpp
/// 在tiled_map.cc的LoadOnPose()中（卸载逻辑）
void TiledMap::LoadOnPose(const SE3& pose) {
    // ... 加载逻辑 ...
    
    // 卸载过远的区块
    for (auto iter = loaded_chunks_.begin(); iter != loaded_chunks_.end();) {
        Vec2i g = *iter;
        int n = abs((g - this_grid)[0]) + abs((g - this_grid)[1]);
        
        if (n > options_.unload_map_size_) {
            // LONG策略：不做任何特殊处理
            // 动态层保留在dynamic_chunks_中，只是从loaded_chunks_移除
            // 内存中的点云数据保持不变
            
            iter = loaded_chunks_.erase(iter);
            LOG(INFO) << "LONG策略：卸载Chunk " << g.transpose() << "，但保留动态层";
        } else {
            iter++;
        }
    }
}

/// 当再次进入该区域时
void TiledMap::LoadOnPose(const SE3& pose) {
    // ...
    
    for (const auto& cp : static_chunks_) {
        if (n <= options_.load_map_size_) {
            auto dyn_iter = dynamic_chunks_.find(cp.first);
            if (dyn_iter != dynamic_chunks_.end()) {
                // LONG策略：动态层仍在内存中，直接使用
                if (!dyn_iter->second->loaded_) {
                    // 实际上对LONG策略，loaded_标志可能一直是true
                    dyn_iter->second->LoadCloud();  // 直接使用内存中的数据
                }
            }
        }
    }
}
```

**NDT匹配时地图构成**：
```
首次进入区域A:
  SetNewTargetForNDT():
    ├─ 静态层: ✅ 区域A静态chunks
    └─ 动态层: ✅ 区域A动态chunks（空，开始累积）
    
离开区域A（卸载）:
  内存状态:
    ├─ loaded_chunks_: 不包含区域A
    └─ dynamic_chunks_: ✅ 仍保留区域A的动态层（30k点）
    
再次进入区域A:
  SetNewTargetForNDT():
    ├─ 静态层: ✅ 区域A静态chunks
    └─ 动态层: ✅ 区域A动态chunks（30k点，继续累积）
```

**生命周期**：
```
T0: 首次进入区域A
  └─► 动态层A: 空

T0~T10: 在区域A内
  └─► 动态层A: 累积（0 → 30k点）

T10: 离开区域A
  └─► 动态层A: 保留在内存（30k点）

T20: 再次进入区域A
  └─► 动态层A: 继续累积（30k → 35k点）

程序退出:
  └─► 动态层A: 丢失（不存盘）

下次启动:
  └─► 动态层A: 空（重新开始）
```

### 3.5 策略4: PERSISTENT策略（永久保留）

```yaml
# 配置（推荐生产环境）
maps:
  dyn_cloud_policy: persistent
  load_dyn_cloud: true            # 启动时加载
  save_dyn_when_quit: true        # 退出时保存
  save_dyn_when_unload: true      # 卸载时保存
  delete_when_unload: false       # 卸载后保留内存
```

**流程特点**：
```cpp
/// 1. 启动时加载（在LoadMapIndex中）
bool TiledMap::LoadMapIndex() {
    // 加载静态地图索引
    LoadStaticChunks();
    
    // PERSISTENT策略：同时加载动态地图
    if (options_.policy_ == DynamicCloudPolicy::PERSISTENT) {
        for (auto& chunk : static_chunks_) {
            std::string dyn_filename = options_.map_path_ + "/" + 
                                      std::to_string(chunk.second->id_) + "_dyn.pcd";
            
            if (PathExists(dyn_filename)) {
                // 创建动态Chunk并加载点云
                auto dyn_chunk = std::make_shared<MapChunk>(
                    chunk.second->id_, chunk.first, dyn_filename);
                dyn_chunk->LoadCloud();  // 从文件加载
                dynamic_chunks_[chunk.first] = dyn_chunk;
                
                LOG(INFO) << "PERSISTENT: 加载动态Chunk " << chunk.first.transpose()
                         << ", 点数: " << dyn_chunk->cloud_->size();
            }
        }
    }
}

/// 2. 运行时更新（与SHORT/LONG相同）
void LidarLoc::Align(CloudPtr input) {
    // 6. 动态地图更新
    if (options_.update_dynamic_cloud_ && loc_success && score_cond &&
        (distance > update_kf_dis_ || time > update_kf_time_)) {
        CloudPtr cloud_world = TransformToWorld(input, current_pose_esti);
        map_->UpdateDynamicCloud(cloud_world, true);
    }
}

/// 3. 卸载时保存
void TiledMap::LoadOnPose(const SE3& pose) {
    // 卸载过远的区块
    for (auto iter = loaded_chunks_.begin(); iter != loaded_chunks_.end();) {
        Vec2i g = *iter;
        int n = abs((g - this_grid)[0]) + abs((g - this_grid)[1]);
        
        if (n > options_.unload_map_size_) {
            auto d = dynamic_chunks_.find(g);
            
            // PERSISTENT策略：卸载时存盘
            if (options_.policy_ == DynamicCloudPolicy::PERSISTENT && 
                d != dynamic_chunks_.end() && d->second->loaded_) {
                
                if (d->second->cloud_ && !d->second->cloud_->empty()) {
                    if (options_.save_dyn_when_unload_) {
                        // 存盘
                        std::string filename = options_.map_path_ + "/" + 
                                             std::to_string(d->second->id_) + "_dyn.pcd";
                        d->second->cloud_->width = d->second->cloud_->size();
                        pcl::io::savePCDFileBinaryCompressed(filename, *d->second->cloud_);
                        
                        LOG(INFO) << "PERSISTENT: 保存动态Chunk " << g.transpose()
                                 << " 到 " << filename;
                    }
                    
                    if (options_.delete_when_unload_) {
                        d->second->Unload();  // 清空内存
                    }
                    // 否则保留在内存中
                }
            }
            
            iter = loaded_chunks_.erase(iter);
        } else {
            iter++;
        }
    }
}

/// 4. 退出时保存
void LidarLoc::Finish() {
    if (options_.map_option_.policy_ == TiledMap::DynamicCloudPolicy::PERSISTENT &&
        options_.map_option_.save_dyn_when_quit_) {
        map_->SaveToBin(true);  // true表示只保存动态层
        LOG(INFO) << "PERSISTENT: 程序退出，保存所有动态地图";
    }
}
```

## 4. 生命周期管理

### 4.1 动态层创建

```cpp
/// 在LoadOnPose()中，当需要加载某个区域时
void TiledMap::LoadOnPose(const SE3& pose) {
    for (const auto& cp : static_chunks_) {
        Vec2i d = cp.first - this_grid;
        int n = abs(d[0]) + abs(d[1]);
        
        if (n <= options_.load_map_size_) {  // 在加载范围内
            auto dyn_iter = dynamic_chunks_.find(cp.first);
            
            if (dyn_iter == dynamic_chunks_.end()) {
                // 该区域还没有动态Chunk，创建一个
                auto new_chunk = std::make_shared<MapChunk>(
                    cp.second->id_, 
                    cp.first, 
                    options_.map_path_ + "/" + std::to_string(cp.second->id_) + "_dyn.pcd"
                );
                
                dynamic_chunks_.emplace(cp.first, new_chunk);
                dynamic_map_updated_ = true;
                
                // PERSISTENT策略：尝试从文件加载
                if (options_.policy_ == DynamicCloudPolicy::PERSISTENT) {
                    if (PathExists(new_chunk->filename_)) {
                        new_chunk->LoadCloud();
                    }
                }
            }
        }
    }
}
```

### 4.2 动态层更新

```cpp
/// 所有策略相同
void TiledMap::UpdateDynamicCloud(CloudPtr cloud_world, bool remove_old) {
    for (size_t i = 0; i < cloud_world->size(); ++i) {
        const auto& pt = cloud_world->points[i].getVector3fMap();
        
        // 确定点所属的Chunk
        Vec2i grid_idx = Pos2Grid(pt.head<2>());
        
        auto chunk_iter = dynamic_chunks_.find(grid_idx);
        if (chunk_iter != dynamic_chunks_.end()) {
            // 添加点到动态Chunk
            chunk_iter->second->cloud_->push_back(cloud_world->points[i]);
            
            // 容量控制
            if (chunk_iter->second->cloud_->size() > options_.max_pts_in_dyn_chunk_) {
                // 降采样或移除旧点
                if (remove_old) {
                    size_t remove_cnt = size_t(0.7 * chunk_iter->second->cloud_->size());
                    chunk_iter->second->cloud_->points.erase(
                        chunk_iter->second->cloud_->points.begin(),
                        chunk_iter->second->cloud_->points.begin() + remove_cnt
                    );
                }
            }
        }
    }
    
    dynamic_map_updated_ = true;
}
```

### 4.3 动态层卸载

| 策略 | 卸载触发 | 内存处理 | 磁盘处理 | 下次加载 |
|------|---------|---------|---------|---------|
| **SHORT** | 距离>300m | 清空(`nullptr`) | 无操作 | 从零开始 |
| **LONG** | 距离>300m | 保留 | 无操作 | 使用内存数据 |
| **PERSISTENT** | 距离>300m | 可选(delete_when_unload) | 存盘 | 从文件加载 |

### 4.4 程序生命周期

```
┌──────────────┐
│ 程序启动      │
└──────┬───────┘
       │
       ├─► 不使用动态地图: 不加载动态层
```

## 5. 适用场景分析

### 5.1 不使用动态地图

**适用场景**：
```
✅ 高度静态环境（仓库、工厂固定产线）
✅ 静态地图质量极高且最新
✅ 环境变化极小
✅ 对内存和计算资源有严格限制
✅ 短期测试、调试
```

**优势**：
- 最低内存占用
- 最快的加载速度
- 最简单的管理
- 无误差累积风险

**劣势**：
```
❌ 无法适应环境变化（停车车辆、移动物体）
❌ 静态地图过时后性能显著下降
❌ 动态区域定位可能失败
❌ 不适合长期运行
```

**实战示例**：
```
场景: 工厂AGV，固定产线
  - 环境: 墙壁、机器位置固定
  - 变化: 仅有移动的AGV和工人
  - 地图: 每月更新一次离线建图
  - 配置: update_dynamic_cloud: false
  
结果:
  Day 1-30: 定位精度高（静态地图准确）
  Day 31-60: 如有布局调整，需重新建图
```

### 5.2 SHORT策略（短期保留）

**适用场景**：
```
✅ 单次测试运行
✅ 测试环境（频繁变化）
✅ 临时路线导航
✅ 调试动态层功能
✅ 环境每次都显著不同
```

**优势**：
- 适应当前会话的环境变化
- 内存占用中等（离开后清空）
- 无磁盘IO开销
- 适合快速测试

**劣势**：
```
❌ 每次启动从零开始
❌ 再次进入区域需重新累积
❌ 不适合固定路线长期运行
❌ 单次运行时间有限时效果不佳
```

**实战示例**：
```
场景1: 停车场测试
  第1圈（首次）:
    - 区域A: 有车A、车B
    - 动态层: 累积车A、车B点云
    - 定位: 正常
  
  离开停车场:
    - 动态层: 清空
  
  第2圈（1小时后）:
    - 区域A: 车A走了，车C来了
    - 动态层: 从零开始，累积车C
    - 定位: 初期可能匹配到车B的旧位置（但已清空）
    
优点: 适应新的车辆布局
缺点: 每次都要重新累积

场景2: 一天多次运行的外卖机器人
  上午运行:
    - 累积餐厅桌椅、临时摊位
    - 动态层: 5000点
    
  程序重启:
    - 动态层: 清空
    
  下午运行:
    - 餐厅布局可能完全不同
    - 适合从零开始
```

### 5.3 LONG策略（长期保留）

**适用场景**：
```
✅ 单次长时间运行（8-12小时）
✅ 固定路线往返
✅ 环境在单次运行内相对稳定
✅ 需要快速适应但不需跨会话保留
✅ 对磁盘IO敏感的系统
```

**优势**：
- 单次运行内完整保留动态层
- 往返同一区域直接使用累积数据
- 无磁盘IO开销
- 适合单日多次经过同一区域

**劣势**：
```
❌ 程序重启后动态层丢失
❌ 内存占用持续增长（单次运行内）
❌ 不适合每天相同路线的长期运行
❌ 无法利用历史累积数据
```

**实战示例**：
```
场景: 物流园区AGV（单班次运行）
  班次时间: 8:00-18:00（10小时）
  
  8:00 启动:
    - 动态层: 空
  
  8:30 第1次经过装货区A:
    - 装货区: 有货物堆A、B
    - 动态层A: 累积（0 → 8000点）
    - 定位分值: 2.1（依赖静态层多）
  
  10:00 离开区域A:
    - 动态层A: 保留在内存（8000点）
  
  14:00 第2次经过装货区A:
    - 装货区: 货物堆变化（A走了，C来了）
    - 动态层A: 继续累积（8000 → 15000点）
    - 定位分值: 2.4（静态+动态融合，更准确）
    
  ✅ 优势: 第2次进入时直接使用累积数据
  
  18:00 班次结束，程序关闭:
    - 动态层A: 丢失（15000点）
  
  次日8:00 重新启动:
    - 动态层: 空（从零开始）
    
  ❌ 劣势: 每天都要重新累积
```

### 5.4 PERSISTENT策略（永久保留，推荐）

**适用场景**：
```
✅ 生产环境长期运行
✅ 固定路线（每天相同）
✅ 环境有缓慢累积变化
✅ 需要跨会话保留环境变化
✅ 7×24小时运行的系统
✅ 定期维护重启的系统
```

**优势**：
- 跨会话保留动态层
- 长期累积环境变化
- 每次启动即可使用历史数据
- 适合生产环境
- 自动适应缓慢变化

**劣势**：
```
❌ 磁盘IO开销（卸载/退出时写入）
❌ 启动时加载时间较长
❌ 需要管理磁盘空间
❌ 可能累积陈旧数据（需定期清理）
```

**实战示例**：
```
场景: 园区无人配送车（长期运行）
  
Day 1:
  启动: 动态层为空
  
  第1次经过办公楼A门口:
    - 停放: 自行车3辆
    - 动态层: 累积自行车点云（3000点）
    - 定位分值: 2.3
  
  退出程序:
    - 保存: A门口_dyn.pcd（3000点）

Day 2:
  启动: 加载A门口_dyn.pcd（3000点）
  
  第1次经过A门口:
    - 停放: 自行车5辆（位置略有不同）
    - 动态层: 继续累积（3000 → 8000点）
    - 定位分值: 2.5（静态+丰富的动态层）
    ✅ 优势: 立即有较高定位质量
  
  退出程序:
    - 保存: A门口_dyn.pcd（8000点，覆盖）

Day 7:
  启动: 加载A门口_dyn.pcd（8000点）
  
  第1次经过A门口:
    - 停放: 电动车2辆（自行车都走了）
    - 动态层: 继续累积（8000 → 10000点）
    - 定位分值: 2.4
    ✅ 优势: 适应了一周的变化模式
  
Month 1 总结:
  - A门口动态层: 25000点（包含多种停车模式）
  - 定位鲁棒性: 显著提升
  - 适应性: 自动适应日常变化
  
Month 3:
  - 可能需要: 检查动态层点数是否过多
  - 可选操作: 清理陈旧数据或重新建图
```

### 7.5 常见问题与解决

#### 问题1: PERSISTENT策略启动很慢

```
原因: 加载大量动态层文件

解决方案1（延迟加载）:
  修改配置:
    load_dyn_cloud: false
  
  效果: 启动快，首次进入区域时按需加载

解决方案2（并行加载）:
  代码修改: 在LoadMapIndex()中使用多线程加载

解决方案3（清理陈旧数据）:
  定期删除长时间未访问的动态层文件
```

#### 问题2: 动态层点数过多，影响性能

```
原因: 长期累积，超过容量限制

解决方案:
  1. 降低max_pts_in_dyn_chunk:
     max_pts_dyn_chunk: 30000  # 从50000降低
  
  2. 更严格的更新门槛:
     update_lidar_loc_score: 2.5  # 从2.2提高
  
  3. 定期重置动态层:
     每月删除一次 *_dyn.pcd 文件
```

#### 问题3: SHORT策略离开区域后再次进入定位差

```
原因: 动态层被清空，需要重新累积

解决方案:
  切换到LONG或PERSISTENT策略
  
  SHORT适合:
    - 环境每次都不同的场景
    - 临时测试
  
  不适合:
    - 固定路线往返
    - 长期运行
```

#### 问题4: 磁盘IO过于频繁

```
原因: save_dyn_when_unload=true

解决方案:
  修改配置:
    save_dyn_when_unload: false  # 关闭卸载时保存
    save_dyn_when_quit: true     # 只在退出时保存
  
  效果:
    - IO次数: 从每次卸载(1500次/天) → 退出时(1次/天)
    - 风险: 异常退出时丢失本次累积数据
  
  折中方案:
    定期保存: 每小时手动发送保存命令
```

## 8. 核心总结

### 8.1 定位流程共性

**所有策略在定位时的共性**：
1. ✅ 都使用 `静态层 + 动态层` 融合地图进行NDT匹配
2. ✅ 都通过 `SetNewTargetForNDT()` 统一添加点云
3. ✅ 都基于点云数量比例实现隐式锚定（无显式权重）
4. ✅ 都受相同的质量门控（score>2.2, LO一致性等）

### 8.2 核心差异点

**唯一的本质区别在于动态层的生命周期管理**：

| 维度 | 不使用 | SHORT | LONG | PERSISTENT |
|------|-------|-------|------|------------|
| **会话内累积** | ❌ | ✅ | ✅ | ✅ |
| **离开区域** | N/A | 清空 | 保留 | 保留+存盘 |
| **跨会话保留** | N/A | ❌ | ❌ | ✅ |
| **定位质量趋势** | 不变 | 单次提升 | 单次提升 | 长期提升 |

### 8.3 选择建议

```
快速决策表:

运行时长     | 环境变化     | 固定路线 | 推荐策略
------------|-------------|---------|----------
< 1小时     | 是          | 否      | SHORT
< 1小时     | 是          | 是      | SHORT
1-8小时     | 是          | 否      | LONG
1-8小时     | 是          | 是      | LONG 或 PERSISTENT
> 8小时     | 是          | 否      | PERSISTENT
> 8小时     | 是          | 是      | PERSISTENT (强烈推荐)
任意        | 否          | 任意    | 不使用动态地图

生产环境默认选择: PERSISTENT
```

### 8.4 最佳实践

1. **初始部署**：
   - 第1周：SHORT策略，观察效果
   - 第2周：切换PERSISTENT，开始累积
   - 第1月：监控动态层增长，调整参数

2. **长期维护**：
   - 每月检查动态层点数
   - 每季度评估是否需要重新建图
   - 重大环境变化后清理动态层

3. **性能优化**：
   - save_dyn_when_unload=false（减少IO）
   - update_kf_dis适当增大（降低更新频率）
   - max_pts_in_dyn_chunk根据实际调整

4. **故障恢复**：
   - 备份关键区域的 *_dyn.pcd 文件
   - 异常后可以选择性恢复或清空
   - 重要区域可以手动调高更新频率
